## Connector and policy acceptance

The disposable Docker integration used real Infisical, OpenBao, PostgreSQL,
and AV containers. It passed:

- optional Basic authentication and managed-browser CRUD/RBAC enforcement;
- owner, operator, and auditor boundaries;
- named-agent creation, rotation, enable/disable, deletion, profile grants,
  route grants, expiry, and revocation;
- Infisical and OpenBao static resolution;
- OpenBao dynamic PostgreSQL issuance, renewal, synchronous child/session
  cleanup, and termination after grant removal;
- Tier 2 named injection, transparent injection, streaming, WebSockets, and an
  exact credentialless tunnel;
- Tier 3 static and dynamic child environments;
- removal of wrapper, connector-authentication, and lease-management inputs
  from children; and
- enforced-container startup, interruption, and cleanup.

The real Cilium cluster fixture proved:

- the declared proxy Service and port remain reachable;
- undeclared direct TCP/443 is blocked;
- link-local cloud metadata is blocked;
- direct UDP traffic is not delivered; and
- the disposable namespace is removed after the proof.

## Private Kubernetes deployment

The downstream deployment keeps its private DNS, ingress, identity, connector,
and provider values outside this repository. Its OpenTofu plan contained one
in-place Helm change, no creates, and no destroys.

After deployment:

- the AV pod ran the exact digest recorded above;
- OpenBao's built-in database engine and Kubernetes auth role passed a
  value-blind audit;
- OpenBao Agent rendered a renewable PostgreSQL login into pod tmpfs;
- no durable Kubernetes database Secret or static OpenBao KV credential
  existed;
- readiness, private HTTPS transport, plaintext rejection, unknown-destination
  rejection, and workload policies passed;
- a graceful pod replacement completed and the live checks remained green;
- a value-blind PostgreSQL 16 dump restored into an unnetworked, digest-pinned
  container with all ten AV schema tables and no production mutation;
- private transport TLS rotated from revision 1 to 2 and the interception CA
  rotated from revision 2 to 3; AV restarted and the live checks passed; and
- Helm rolled back to the exact v0.4.1 digest successfully, passed the live
  checks, then the Git-managed workflow restored the exact v0.5.0 digest and
  repeated the live and restore checks.

The cluster's scheduled PostgreSQL backup was Ready before the upgrade. Actual
production database mutation and issuer recovery remain documented
break-glass procedures, not routine acceptance actions.

## Authentication status and exception

Production is OIDC-only. Optional Basic and full managed RBAC behavior passed
in the disposable integration environment so no production password was
introduced solely for a test.

Live Google Secret Manager Workload Identity Federation remains the explicit
exception tracked by [#13](https://github.com/noeljackson/av/issues/13). The
connector's ADC/WIF, checksum, IAM-denial, bounds, Tier 2, and Tier 3 contract
tests pass, but this deployment has no authorized Google Cloud project or
workload-identity pool with which to perform the live proof. Issue #27 remains
open until that external authority exists and the live WIF result is added to
this record.
